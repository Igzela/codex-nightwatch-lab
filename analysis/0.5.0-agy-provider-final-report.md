## 1. Executive Summary

Nightwatch 0.5.0 successfully expands Nightwatch from a single-provider Codex supervisor into a multi-provider unattended control plane supporting both **Codex** and **Google Antigravity CLI (AGY)** without regressions, compromising zero-runtime-dependency constraints, or weakening Codex guarantees.

### Key Architectural Deliverables:
1. **Provider Abstraction Architecture (`nightwatch/nightwatch/providers.py`)**:
   - `ProviderAdapter` abstract base class defining the provider execution contract (`run_turn`, `build_command`, `probe_quota`, `find_active_processes`, `auth_sanity`, `list_models`, `doctor_check`).
   - `CodexProviderAdapter` preserving 100% existing Codex behaviors and interfaces.
   - `AgyProviderAdapter` implementing the AGY CLI execution, NDJSON streaming parser, exact conversation lifecycle, and live `/usage` quota authority.
2. **Exact Conversation Identity Guarantee**:
   - Resuming an AGY conversation strictly uses `--conversation <EXACT_UUID>`.
   - Never uses heuristic or ambiguous continuation flags (`-c`, `--continue`).
   - Detects AGY stderr warnings (`warning: conversation "<ID>" not found`) or UUID mismatches on `init` and immediately fails closed with `ErrorKind.STATE`.
3. **Authoritative Live Quota Tracking via AGY CLI**:
   - AGY provides a native, non-destructive `/usage` command: `agy --output-format stream-json -p /usage`.
   - Probing burns **0 AI tokens** and runs in <10 seconds.
   - Accurately tracks primary (5h) and secondary (weekly) rate limit windows, fractional remaining budgets, and ISO-8601 UTC reset timestamps converted into epoch timestamps.
   - Supports live quota wait and recovery loop (`WAIT_QUOTA` -> `RECOVERING` -> `RUNNING`).
4. **Single-Account & Process Isolation**:
   - Enforces `CURRENT_ONLY` mode for AGY; fails closed against `AUTO_POOL`.
   - Checks active Linux processes by PID and starttime to prevent concurrent overlapping CLI executions in the same workspace.
5. **Systemd User Service Integration**:
   - Generates repo-bound user systemd service units with `Environment="PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin"`.
   - Validated cleanly with `systemd-analyze verify`.

## 6. Post-Release Clarification & Addendum (0.5.1 Audit)

> [!NOTE]
> **Systemd Scope Clarification**: The `REAL_SYSTEMD_SMOKE` gate performed in 0.5.0 validated unit-file generation, installation, PATH environment configuration, and syntax correctness using `systemd-analyze verify` (`SYSTEMD_UNIT_SYNTAX = PASS`). It did *not* execute live provider turns under active `systemctl --user` supervision. True multi-turn provider execution, exact conversation resume across turns under systemd supervision, and clean transient unit teardown were formally tested and verified in Nightwatch 0.5.1 (`REAL_AGY_SYSTEMD_EXECUTION` and `REAL_AGY_SYSTEMD_CONVERSATION_RESUME`).
