**Generated:** 2026-09-03

## 1. Executive Summary

Nightwatch 0.4.1 introduced segmented event storage under `<control-plane-dir>/events/` with `manifest.json`, resolving the previous 1 MB lifetime ceiling and $O(N^2)$ full-history read amplification. However, a transactional crash gap remained during active segment rotation:
If a crash occurred after a new segment was created and written but before the manifest was atomically updated on disk, restart verification observed directory entries mismatching the manifest, failing closed with `StateIntegrityError`.

Nightwatch 0.4.2 closes this crash window without redesigning the event store. When the manifest and events directory disagree upon restart:
1. Nightwatch verifies previous manifest structure, previous sealed segments, and previous active segment integrity.
2. If exactly one unexpected entry exists matching the uniquely provable next segment name (`segment-{N:06d}.jsonl`) as a regular file (no symlink/directory):
   - **Case 1 (Empty orphan):** Safely deleted/reset; manifest frontier remains unchanged.
   - **Case 2 (Incomplete/partial atomic append):** Safely discarded/unlinked; manifest frontier remains unchanged.
   - **Case 3 (Complete valid event with `seq == manifest.last_seq + 1`):** Previous active segment is sealed with its SHA256 digest, the new segment entry is reconstructed, and the frontier is atomically committed to `manifest.json`.
   - **Case 4 (Malformed JSON complete record):** Fails closed with `StateIntegrityError`.
   - **Case 5 (Orphan sequence skips or repeats):** Fails closed with `StateIntegrityError`.
   - **Case 6 (Multiple unexpected orphans):** Fails closed with `StateIntegrityError`.
   - **Case 7 (Symlink, directory, or unexpected filename):** Fails closed with `StateIntegrityError`.

All broad `except Exception: pass` paths were audited and eliminated from trusted storage resolution.

## 2. Integrity & Frontier Complexity Distinction

- **Routine Frontier Validation (`_validate_event_frontier` / `load_state`):**
  - **Metadata verification:** $O(S)$ where $S$ is the number of segments. Inspects manifest structural integrity, sequence range continuity, and invokes `os.lstat()` to verify sealed segment existence, file mode, and exact recorded byte size.
  - **Historical body reads:** Strict $O(1)$. Sealed historical segment bodies are *never* read from disk. Only the active segment tail (and an orphan next segment candidate during crash recovery) is read.
- **Full History Retrieval (`load_events`):**
  - Reads and parses full event lines across all segments, verifying the complete SHA-256 digest chain across all sealed segments and confirming global monotonic sequence continuity.
